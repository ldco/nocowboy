# Reflection: Code Complete — Steve McConnell

**Read:** 2026-07-02
**Impact:** The definitive practical guide to software construction.

## Core Insights

### 1. Construction Is the Core
Requirements, design, testing — all important. But construction (actual coding) is where the rubber meets the road. This is where quality is really made or broken.

### 2. Managing Complexity
The single most important skill in programming: managing complexity. Humans can hold ~7 items in working memory. Good code breaks problems into chunks that fit in one human brain.

### 3. Design in Construction
Design isn't a separate phase — it happens throughout construction. Good programmers design as they code. Bad programmers either over-design or don't design at all.

### 4. Defensive Programming
Assume inputs will be wrong. Assume other code will be buggy. Protect yourself. Assertions are not debugging tools — they're design tools.

### 5. The Power of High-Quality Routines
Good routines are short, do one thing, have good names. The difference between amateur and professional code.

### 6. The Software-Development Quagmire
Most projects fail not because of technology but because of people and process. McConnel advocates for evolutionary delivery — iterative, feedback-driven development.

## Principle Extracted
**Complexity is the enemy.** The primary job of software engineering is managing complexity. Everything else is secondary.
