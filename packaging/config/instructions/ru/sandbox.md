# Sandbox-исполнение

При выполнении потенциально деструктивных или недоверенных операций используй sandbox-исполнение.

## Типы Sandbox (в порядке приоритета)

### 1. Правила разрешений (встроенные)
nocowboy.json уже содержит правила разрешений для деструктивных команд. Это первая линия обороны.

### 2. Read-Only верификация
Перед запуском деструктивных команд:
- Флаги `--dry-run` где доступны
- Режим предпросмотра для файловых операций
- `ls` перед `rm`, review перед `mv`

### 3. Docker Sandbox
Для компиляции/запуска недоверенного кода:
```
docker run --rm -v $(pwd):/work -w /work node:22 npm test
docker run --rm -v $(pwd):/work -w /work python:3.12 pytest
```

### 4. Firejail (если установлен)
Для общей изоляции команд:
```
firejail --seccomp --private-tmp <command>
```

## Когда использовать Sandbox

- Запуск недоверенного кода из зависимостей (node_modules, vendor/)
- Выполнение файлов, загруженных пользователем
- Запуск команд сборки в CI-подобных сценариях
- Тестирование компиляции неизвестных/бинарных пакетов
- Любая команда с `eval`, `exec` или динамической загрузкой кода

## Безопасность окружения

- Никогда не передавай секреты в sandbox-контейнеры
- Используй read-only монтирования томов, когда возможно
- Устанавливай лимиты ресурсов: `docker run --memory=512m --cpus=2`
