# Путевые правила

Некоторые инструкции применяются только при работе над определёнными частями кодовой базы. Они определяются в `instructions/rules/*.md` с frontmatter `paths:`.

## Как это работает

Когда ты начинаешь работать над файлом, проверь, подходят ли какие-либо путевые правила. Правило с:

```yaml
---
paths:
  - "src/api/**/*.ts"
---
```

применяется, когда ты читаешь или редактируешь файлы в `src/api/`.

## Разделы

| Файл | Применяется к | Темы |
|------|---------------|------|
| `rules/api-patterns.md` | `**/*.api.ts`, `src/routes/**` | API-конвенции, форматы ошибок |
| `rules/database.md` | `**/db/**`, `**/schema/**`, `**/migrations/**` | Паттерны доступа к БД, правила миграций |
| `rules/frontend.md` | `src/components/**`, `src/pages/**` | UI-конвенции, паттерны компонентов |

## Загрузка правил

Когда ты читаешь или редактируешь файл:
1. Проверь его путь по всем паттернам `paths:` правил
2. Если совпало — загрузи содержимое правила в контекст
3. Примени инструкции правила к своей работе

## Формат

Каждый файл правил — это markdown с YAML frontmatter:

```markdown
---
paths:
  - "src/api/**/*.ts"
  - "server/routes/**"
---

# Правила разработки API

- Все endpoint'ы должны валидировать входные данные через Zod
- Возвращай единый формат ошибок: { error: { code, message } }
- Используй существующий rateLimiter middleware для всех публичных endpoint'ов
```

Поле `paths` использует glob-паттерны:
- `**/*.ts` — все TypeScript файлы везде
- `src/**/*.{ts,tsx}` — TS/TSX файлы в src/
- `config/*.yaml` — YAML файлы в config/
