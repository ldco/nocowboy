# Автоматическая память

## Что это

Auto memory накапливает знания между сессиями через NUTAUSIK. Каждое значимое открытие, паттерн или предпочтение сохраняется в NUTAUSIK brain и загружается при старте сессии.

Это НЕ замена AGENTS.md. AGENTS.md = инструкции, которые ты пишешь. Auto memory = знания, обнаруженные в работе.

## Хранение

Вся память живёт в NUTAUSIK. Используй `nutausik_memory_add` для каждого сохранения. Типы:

| Тип | Когда | Пример |
|-----|-------|--------|
| `pattern` | Повторяющиеся наблюдения | "Каждый деплой требует миграции БД" |
| `gotcha` | Найденные грабли | "Пропущенный .env вызывает тихий 500" |
| `convention` | Решения команды/проекта | "Используем pnpm, не npm" |
| `context` | Знание о проекте | "API base URL: https://api.example.com/v2" |
| `dead_end` | Подходы, которые не сработали | "Пробовали X, не работает из-за Y" |

## Старт сессии

Запусти `nutausik_memory_block` или `nutausik_memory_surface` при старте. Отметь релевантные записи в разговоре.

## В работе

Сохраняй, когда находишь:
- Команды сборки/тестов — `npm run dev`, `cargo build`, `pytest tests/`
- Инсайты по отладке — "Модуль auth падает из-за X"
- Архитектурные паттерны — "Компоненты в src/components/, страницы в src/pages/"
- Предпочтения пользователя — "Всегда используй pnpm", "отступы 2 пробела"
- Грабли — "Не используй raw SQL, всегда Drizzle ORM"
- Частые ошибки — "Забыл запустить миграцию → таинственная 500"

Используй: `nutausik_memory_add(type: "...", title: "...", content: "...")`

## Завершение сессии

Перед завершением: запусти `/dream` или вызови `nutausik_memory_add` для ключевых уроков.

## Поиск

- `nutausik_memory_search(query)` — полнотекстовый поиск по всей памяти
- `nutausik_fts_search(query)` — FTS5 для точных запросов
- `nutausik_memory_list(type: "gotcha")` — фильтр по типу
