# Channels — Отправка событий в запущенные сессии

Channels позволяют получать сообщения от внешних инструментов (CI, алерты, чат) во время сессии. Агент проверяет сообщения в начале каждого шага и реагирует на них.

## Как это работает

1. Внешние инструменты POST-ят JSON на webhook endpoint
2. Сообщения сохраняются в `~/.nocowboy/channels/<channel>.json`
3. Агент вызывает `channels_read()` в начале каждого шага
4. Сообщения очищаются после прочтения

## Настройка

### Запуск webhook-слушателя (фон)

```
channels_listen(port: 9337)
```

Или из терминала:
```bash
channels_listen(port: 9337)
```

### Отправка сообщения

Из любого инструмента:
```bash
curl -X POST http://127.0.0.1:9337 \
  -H "Content-Type: application/json" \
  -d '{"channel":"ci","from":"github-actions","message":"Тесты проходят? PR #42 нуждается в ревью"}'
```

### Чтение сообщений (агент делает это автоматически)

```
channels_read()
channels_read(channel: "ci")
```

### Отправка напрямую из MCP

```
channels_post(channel: "ci", from: "github-actions", message: "Build #123 прошёл")
```

## Стандартные каналы

| Канал | Источники | Ожидаемые сообщения |
|-------|-----------|---------------------|
| `ci` | GitHub Actions, GitLab CI | Прохождение/падение сборки, результаты тестов |
| `alerts` | Sentry, Datadog, Grafana | Всплески ошибок, алерты производительности |
| `chat` | Slack webhook, Discord | Сообщения команды, упоминания |
| `review` | GitHub PR webhook | PR открыт, запрошено ревью |
| `deploy` | ArgoCD, Jenkins | Статус деплоя |

## Поведение агента

В НАЧАЛЕ каждого шага:
1. Вызови `channels_read()` чтобы проверить новые сообщения
2. Если есть сообщения — обработай их:
   - **ci failures**: исследуй и исправь
   - **alerts**: сопоставь с недавними изменениями
   - **chat**: подтверди получение и ответь
   - **review requests**: переключись в режим ревью
3. Сообщи пользователю: «Получено N сообщений из каналов: [summary]»
