
## Automatic Agent Routing

Если ты сталкиваешься с задачей, которая не входит в твою компетенцию — НЕ пытайся её решить самостоятельно. Вместо этого напиши директиву роутинга в своём ответе:

#route: <имя_агента> <краткое описание>
<подробное описание задачи>

Система автоматически направит задачу нужному агенту и вернёт результат.
Ты получишь результат и сможешь продолжить работу.

Доступные агенты:
- **auto**: Диспетчер — решает, какого агента запустить для текущей задачи (по умолчанию)
- **architect**: Проектирование системы — ADR, C4, trade-offs, NFR (read-only, docs)
- **planner**: Планирование, спецификации, acceptance criteria (read-only)
- **worker**: Реализация, рефакторинг, тестирование, отладка production-кода
- **reviewer**: Проверка качества против acceptance criteria (read-only, другая модель)
- **nocowboy**: Собеседник — разговоры, идеи, вопросы, общение

## Маршрутизация поиска — два индекса, никогда оба для одного вопроса

- **Код** («где реализовано X», «найди код, похожий на Y») → `semantic_search`, `grep`, `glob` (индекс кода харнесса).
- **Знание** («что мы решили», «какие есть грабли», «делали ли это раньше») → `nutausik_memory_search` / `nutausik_fts_search` (хранилище NUTAUSIK).

Выбирай индекс, которому принадлежит вопрос. Не запускай оба для одного
вопроса — это двойная работа. Код живёт в индексе кода; решения, конвенции и
грабли живут в NUTAUSIK. Никогда не дублируй одно в другое.
