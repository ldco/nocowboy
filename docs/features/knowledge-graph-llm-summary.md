# LLM-сводка архитектуры по AST-графу

> **ID:** `knowledge-graph-llm-summary`
> **Status:** `done`
> **Version:** `v1.1.0`

## Что это

Текстовая сводка архитектуры проекта, построенная из AST-графа
(`knowledge-graph-ast-engine`): сколько файлов/символов/рёбер, как файлы
распределены по архитектурным слоям и какие символы — самые нагруженные хабы
(больше всего входящих рёбер). Структурные факты считаются чисто; повествование
пишет **инжектированный** LLM, результат кэшируется по хэшу структуры графа.

## Дизайн

- `graphOutline(snapshot, { topHubs?, layerRules? })` — чистые факты:
  `files`, `symbols`, `edges {import,call,contains}`, `layers` (по файлам,
  unknown-бакет включён) и `hubs` (топ по входящим рёбрам, tie-break по id).
- `renderOutline(outline)` — стабильный текстовый блок (он же промпт для LLM).
- `graphHash(snapshot)` — детерминированный хэш структуры (независим от порядка
  узлов/рёбер), ключ кэша.
- `summarizeArchitecture(snapshot, { llm, cache?, outline? })` → `{ summary,
  outline, cached }`: строит outline, рендерит промпт, отдаёт кэш или зовёт
  `llm`, кладёт результат в кэш. Без кэша — просто каждый раз зовёт `llm`.

## Граница (что НЕ делает)

Модуль сам **не ходит** в провайдера/модель: LLM — инжектируемая функция
(`llm(prompt, outline)`), поэтому он юнит-тестируется стабом, детерминирован и
не тянет сеть. Реальный вызов модели — на стороне вызывающего (агент/команда).

## Проверка

```bash
cd packages/opencode
bun test test/nocowboy/knowledge-graph-summary
```

Покрыто: подсчёт files/symbols/рёбер по видам; раскладка по слоям; ранжирование
хабов и `topHubs`; пустой граф → нули и `(none)`; детерминированный и
порядко-независимый `graphHash`; `summarizeArchitecture` зовёт `llm` один раз и
кэширует по структуре, смена структуры → новый вызов.
