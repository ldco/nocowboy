## 3. Корневая причина: инвалидация префикс-кеша DeepSeek

### 3.1 Как работает кеш DeepSeek

DeepSeek использует **префиксное кеширование**: если начало промпта совпадает с предыдущим запросом, эти токены помечаются как `cache_hit` и стоят **в 120 раз дешевле** (для Pro).

| Тип токенов | Цена за 1M (Pro) | Цена за 1M (Flash) |
|-------------|-------------------|---------------------|
| input cache_hit | $3.63 | $2.80 |
| input cache_miss | **$435.00** | $140.00 |
| output | $870.00 | $280.00 |

Разница cache_hit/cache_miss: **×120 для Pro, ×50 для Flash**.

### 3.2 Динамика cache_miss (Pro)

| Дата | Pro cache_miss | Рост | Стоимость cache_miss |
|------|----------------|------|----------------------|
| 01 | 1,043,180 | — | $0.45 |
| 04 | 4,282,357 | ×4.1 | $1.86 |
| 14 | 422,331 | — | $0.18 |
| 17 | 466,869 | — | $0.20 |
| **18** | **17,671,806** | **×37.9** | **$7.69** |
| **19** | **16,266,399** | — | **$7.08** |
| **21** | **11,815,204** | — | **$5.14** |

**17.7M cache_miss токенов 18 июля = $7.69 из $8.05 дневной стоимости Pro (95%).**

### 3.3 Средняя стоимость одного Pro-запроса

| Дата | $/запрос (Pro) |
|------|-----------------|
| 01–17 | ~$0.005 |
| **18–21** | **~$0.042** (×8.4) |

То есть каждый вызов архитектора или надзирателя стал стоить в 8 раз дороже. Не потому что «больше работы», а потому что кеш перестал работать.

## 4. Что ломает префикс-кеш

Системный промпт собирается в `packages/opencode/src/session/system.ts` (функция `environment()`). Порядок блоков:

```typescript
// 1. СТАТИЧЕСКИЙ — модель, дата, платформа, git
envLines = NoCowboySystemPrompt.environment({...})

// 2. ДИНАМИЧЕСКИЙ — Repository Map
//    ❌ Перегенерится при КАЖДОМ изменении .git/index (mtime)
//    ❌ .git/index меняется при любом git add/commit — т.е. ПОСТОЯННО
repomap = RepoMap.generate(dir, 40)

// 3. ДИНАМИЧЕСКИЙ — NUTAUSIK memory_block
//    ❌ Разный для каждой сессии (накопление памяти)
fetchContext() → nutausik_memory_block

// 4. ДИНАМИЧЕСКИЙ — NUTAUSIK coherence_check
//    ❌ Меняется между сессиями
fetchCoherenceCheck()

// 5. ДИНАМИЧЕСКИЙ — NUTAUSIK handoff
//    ❌ Уникальный для каждой сессии
fetchHandoff() → nutausik_handoff_load

// 6. СТАТИЧЕСКИЙ — Roadmap Spec Check
//    ⚠️ Статический, но добавляет 25+ строк мусора в каждую сессию

// 7. ДИНАМИЧЕСКИЙ — PM v3 context
//    ❌ Добавляется если проект Puppet Master
fetchPmContext(dir)

// 8. СТАТИЧЕСКИЙ — AGENTS.md + 9 rules-файлов (37KB)
//    Загружается через Instruction.system()
```

**Ключевая проблема:** динамические блоки (2–5, 7) вставлены МЕЖДУ статическими (1, 6, 8). Из-за этого при ЛЮБОМ изменении динамического блока весь последующий статический контент тоже становится `cache_miss`.

### 4.1 Почему именно Pro страдает сильнее

Pro используется агентами **architect** и **overseer** (конфиг: `abccd97b7`, 11 июля). Эти агенты:
- Запускаются в новых сессиях (каждый `#route` или task tool создаёт свежую сессию)
- Каждая новая сессия = новый handoff + новый memory_block = **100% cache_miss для всего промпта**
- Цена cache_miss для Pro в 3.1 раза выше чем для Flash ($435 vs $140/1M)

В то время как Flash (агенты auto/code/debug):
- Чаще работают в длинных сессиях (префикс остаётся стабильным)
- Цена cache_miss в 3.1 раза ниже

## 5. Факторы, приведшие к взрыву стоимости

### Фактор A: Раздутие статического промпта (×260 рост)

| Компонент | Было (июнь) | Стало (июль) | Рост |
|-----------|-------------|--------------|------|
| AGENTS.md | 1 строка | 107 строк | ×107 |
| rules/*.md | 0 файлов | 9 файлов, 541 строка | ∞ |
| **Итого статика** | ~50 токенов | **~13,000 токенов** | **×260** |

Каждые 13,000 токенов статики при cache_miss стоят **$0.0057** (Pro) или **$0.0018** (Flash). При 191 Pro-запросе в день это $1.09 — только за статику.

Но реальный ущерб больше: статика тянет за собой ВЕСЬ последующий контент (roadmap check, rules, prompt template) в cache_miss.

### Фактор B: Roadmap Spec Check (25+ мусорных директив)

Коммит `fbd5c1a9b` (10 июля) — `system.ts: roadmap spec check injected into system prompt`.

25 фич без спек инжектятся в КАЖДУЮ сессию как:
```
## ⚠️ Roadmap Spec Check
These features have NO spec. You MUST process them before ANY user interaction:
#route: architect write spec for "Publish: npm org @nocowboy..." (publish-npm)
#route: architect write spec for "Deep Context (2M tokens...)" (deep-context-2m)
... +20 more
```

Это заставляет модель тратить токены на обработку директив, которые она не может выполнить (агент `auto` не умеет писать спеки, `#route` для этого использует task tool). Мусор.

### Фактор C: Repomap fingerprint на .git/index mtime

`repomap.ts` (строка 166):
```typescript
return stat.mtimeMs  // .git/index mtime
```

`.git/index` обновляется при **любой** git-операции: `git add`, `git commit`, даже `git status` (если есть изменения в рабочем дереве). Каждое изменение mtime → repomap перегенерится → **префикс-кеш инвалидирован**.

В сессии, где агент активно коммитит, кеш ломается после каждого коммита.

### Фактор D: NUTAUSIK handoff + memory_block — уникальны для каждой сессии

`fetchHandoff()` загружает handoff предыдущей сессии. Каждая сессия имеет уникальный handoff → системный промпт УНИКАЛЕН для каждой сессии → **0% cache_hit при старте новой сессии**.

`fetchContext()` загружает `memory_block` — последние 10 записей памяти. С каждым новым `memory_add` блок меняется.

### Фактор E: Утяжелённое использование Pro 18–19 июля

18 июля: 191 Pro-запрос (против 46 днём ранее). 19 июля: 358 Pro-запросов.

Каждый Pro-запрос с раздутым промптом и сломанным кешем = $0.042. Для сравнения: Flash-запрос со сломанным кешем = $0.0034.

## 6. План исправления

### 🚨 Критические (немедленно)

#### Fix 1: Стабилизировать префикс системного промпта
**Файл:** `packages/opencode/src/session/system.ts`
**Суть:** Весь динамический контент (repomap, NUTAUSIK handoff/context, PM context) должен идти ПОСЛЕ всего статического. Не перемешиваться.

**Было:**
```
[env] → [repomap] → [NUTAUSIK] → [roadmap] → [PM] → [rules]
```

**Должно стать:**
```
[env] → [roadmap] → [rules] → [AGENTS.md] → [repomap] → [NUTAUSIK] → [PM]
                ↑ СТАТИКА                      ↑ ДИНАМИКА
```

Это гарантирует что статический префикс всегда одинаков и кешируется между сессиями.

#### Fix 2: Починить repomap fingerprint
**Файл:** `packages/opencode/src/nocowboy/repomap.ts`
**Суть:** Использовать хеш (SHA256) дерева файлов вместо `.git/index mtime`. Либо кешировать repomap на время сессии и не перегенеривать.

**Вариант A:** Хеш от списка файлов + их размеров (быстро, не читает содержимое)
**Вариант B:** Не инвалидировать repomap внутри сессии вообще (он не меняется критично за время одной сессии)

#### Fix 3: Убрать roadmap spec check из системного промпта
**Файл:** `packages/opencode/src/session/system.ts`
**Суть:** 25+ директив `#route` не должны инжектиться в каждую сессию. Это startup-check, который должен срабатывать ОДИН раз при запуске TUI и создавать задачи в NUTAUSIK, а не висеть в промпте вечно.

### ⚡ Важные (на этой неделе)

#### Fix 4: Сократить rules-файлы
**Файлы:** `.nocowboy/rules/*.md`
**Суть:** 9 файлов (541 строка, 25.6KB) → объединить в 3-4 токен-оптимизированных. Убрать дублирование (стержень описан в AGENTS.md, русский-стержень.md, защита-стержня.md).

#### Fix 5: Не инжектить PM context без необходимости
**Файл:** `packages/opencode/src/session/system.ts`, `nutausik-client.ts`
**Суть:** `fetchPmContext()` вызывается для каждого проекта при старте. Если PM MCP не запущен — таймаут 2 секунды. Сделать lazy: инжектить только когда агент пишет код для PM-проекта (определять по наличию `puppet-master.config.ts`).

#### Fix 6: Кешировать system prompt на уровне TUI-сессии
**Файл:** `packages/opencode/src/session/system.ts`
**Суть:** `environment()` вызывается для каждого нового сообщения. Системный промпт должен собираться ОДИН раз за сессию и переиспользоваться. Динамические блоки (repomap) — обновлять не чаще чем раз в 5 минут.
