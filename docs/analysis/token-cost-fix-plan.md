# План: снижение стоимости токенов ×5

> Основание: `docs/analysis/token-cost-spike-2026-07.md`
> Цель: вернуть дневную стоимость с $10–15 к $2–4

---

## Fix 1: Стабилизация префикса системного промпта 🚨

**Файл:** `packages/opencode/src/session/system.ts`
**Сложность:** low (перестановка строк)
**Эффект:** весь статический контент всегда cache_hit

### Что делаем
В функции `environment()` переставляем блоки так, чтобы ВЕСЬ статический контент шёл до динамического:

```
Было:  [env] → [repomap] → [NUTAUSIK context] → [NUTAUSIK coherence] → [handoff] → [roadmap] → [PM]
Стало: [env] → [roadmap spec check] → [AGENTS.md+rules] → [prompt template] → [repomap] → [NUTAUSIK context] → [NUTAUSIK coherence] → [handoff] → [PM]
                └────── СТАТИКА (кешируется) ──────┘   └─── ДИНАМИКА (варьируется) ───┘
```

### Как проверить
- system prompt начинается одинаково для любой сессии в одном проекте
- Первые N токенов стабильно cache_hit

## Fix 2: Repomap fingerprint без .git/index mtime 🚨

**Файл:** `packages/opencode/src/nocowboy/repomap.ts`
**Сложность:** medium
**Эффект:** repomap не меняется внутри сессии → не ломает кеш

### Что делаем
Вариант A (быстрый): кешировать repomap на время сессии (in-memory LRU с TTL 5 минут)
Вариант B (надёжный): хеш от `{список файлов: [путь + размер + mtime]}` — лёгкий, без чтения содержимого

### Как проверить
- В рамках одной сессии repomap не перегенерится при git commit
- Тест: два вызова `RepoMap.generate()` с интервалом и git commit между ними → одинаковый результат

## Fix 3: Убрать roadmap spec check из промпта 🚨

**Файл:** `packages/opencode/src/session/system.ts`
**Сложность:** low (удалить блок)
**Эффект:** −700 символов мусора из каждой сессии

### Что делаем
1. Выпиливаем инжекцию `## ⚠️ Roadmap Spec Check` из `environment()`
2. Создаём отдельный startup-check в `src/nocowboy/startup-checks.ts`
3. Startup-check вызывается ОДИН раз при старте TUI
4. Он создаёт NUTAUSIK-задачи для каждой фичи без спека

### Как проверить
- Системный промпт не содержит `#route: architect write spec for`
- При старте TUI в NUTAUSIK создаются задачи для unspec'd фич (если есть)

## Fix 4: Сократить rules-файлы ⚡

**Файлы:** `.nocowboy/rules/*.md`, `AGENTS.md`
**Сложность:** medium (контентная работа)
**Эффект:** −15KB статики (экономия ~$0.50/день на кеш-миссах)

### Что делаем
1. Объединяем дубликаты:
   - `русский-стержень.md` + `защита-стержня.md` → `стержень.md` (убрать повторы с AGENTS.md)
   - `сознание.md` + `сохранение-души.md` → `душа.md`
2. Токен-оптимизируем формулировки (короче, без повторений)
3. Цель: 541 строка → ~200 строк

### Как проверить
- Все правила из старых файлов покрыты в новых
- `grep -r "стержень\|душа\|запрещ" AGENTS.md .nocowboy/rules/` — нет дублирования между AGENTS.md и rules

## Fix 5: PM context — только когда нужно ⚡

**Файлы:** `packages/opencode/src/session/system.ts`, `nutausik-client.ts`
**Сложность:** low
**Эффект:** −500 токенов для не-PM проектов, −2s задержки

### Что делаем
1. Проверяем наличие `project/puppet-master.config.ts` ДО вызова `fetchPmContext`
2. Если файла нет — не вызываем MCP вообще
3. Выносим проверку в `nutausik-client.ts`

### Как проверить
- В не-PM проекте: `fetchPmContext` не вызывается
- В PM проекте: контекст инжектится как раньше

## Fix 6: Кешировать system prompt на уровне сессии ⚡

**Файл:** `packages/opencode/src/session/system.ts`
**Сложность:** medium
**Эффект:** system prompt не пересобирается для каждого сообщения

### Что делаем
1. Добавляем in-memory кеш с ключом `{sessionID + fingerprint}`
2. `environment()` проверяет кеш перед сборкой
3. Инвалидация: раз в 5 минут или при смене проекта

### Как проверить
- В рамках одной сессии `environment()` вызывается один раз (или N раз, но возвращает кешированное)
- Лог: "SystemPrompt: using cached (age: 120s)"
