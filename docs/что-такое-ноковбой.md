# NoCowboy: откуда мы пришли и зачем всё это

> Файл для русских разработчиков. Вся информация проверена по первоисточникам
> (GitHub-репозитории, README, официальная документация) на 14 июля 2026 года.

---

## 1. OpenCode — начало

**OpenCode** (`github.com/opencode-ai/opencode`) — это оригинальный open-source
AI-кодинг ассистент для терминала. Написан на **Go**. Использует TUI-фреймворк
Bubble Tea от Charm. Предоставляет:

- Интерактивный терминальный интерфейс (TUI)
- Поддержку множества AI-провайдеров: OpenAI, Anthropic Claude, Google Gemini,
  AWS Bedrock, Groq, Azure OpenAI, OpenRouter
- Управление сессиями (сохранение в SQLite)
- Интеграцию с LSP (Language Server Protocol) для понимания кода
- MCP (Model Context Protocol) для подключения внешних инструментов
- Инструменты: glob, grep, view, write, edit, bash, fetch

OpenCode получил **13 500 звёзд** на GitHub, был под MIT-лицензией.

**18 сентября 2025 года** оригинальный архив был заморожен (archived).
Автор (из команды Charm) продолжил разработку под именем **Crush**
(`github.com/charmbracelet/crush`), который сейчас имеет 26 600+ звёзд.
Crush — это уже не pure MIT, а FSL-1.1-MIT лицензия.

## 2. Kilo Code — форк OpenCode в TypeScript

**Kilo Code** (`github.com/Kilo-Org/kilocode`) — это **НЕ прямой форк
OpenCode на Go**. Это принципиально другой проект:

- Написан на **TypeScript + Bun** (не Go)
- В README прямо сказано: *"Kilo CLI is a fork of OpenCode, enhanced to work
  within the Kilo agentic engineering platform"*
- Имеет **26 200+ звёзд** на GitHub
- MIT-лицензия
- 25 473 коммита, 456 релизов

### Что Kilo Code добавил сверх OpenCode:

| Компонент | Описание |
|-----------|----------|
| **VS Code Extension** | Полноценное расширение для Visual Studio Code |
| **JetBrains Plugin** | Нативный плагин на Kotlin (12% кодовой базы) |
| **CLI** | npm-пакет `@kilocode/cli`, нативная компиляция под все платформы |
| **500+ моделей** | Собственное API-роутинг через kilo.ai, нулевая наценка |
| **Inline autocomplete** | Ghost-text подсказки, принятие по Tab |
| **Agent Manager** | Worktree-базированные параллельные сессии |
| **Voyage AI + LanceDB** | Семантический поиск по коду через эмбеддинги |
| **Tree-sitter** | AST-парсер для понимания кода (37 WASM-парсеров) |
| **SolidJS + OpenTUI** | Современный TUI-фреймворк (не Bubble Tea) |
| **Встроенные агенты** | Code, Plan, Ask, Debug, Review |
| **MCP Marketplace** | Поддержка Model Context Protocol |
| **Cloud Agent** | `app.kilo.ai/cloud` — запуск из браузера |

Kilo Code — это **полноценная платформа**: VS Code + JetBrains + CLI + Cloud.
OpenCode был только CLI для терминала. Kilo — это commercial-grade продукт
с открытым исходным кодом.

## 3. Почему именно Kilo Code, а не OpenCode

Выбор Kilo Code как базы для NoCowboy был стратегическим решением.

**Почему НЕ OpenCode:**
- OpenCode на **Go** — наша команда работает с **TypeScript/Bun**. Форк Go-проекта
  означал бы полную переписку или разделение стеков.
- OpenCode **архивирован** и не развивается. Crush (продолжение) — на Go и
  с другой лицензией (не MIT).
- У OpenCode нет экосистемы — только CLI без IDE-расширений.
- Всего 13 500 звёзд (против 26 200 у Kilo).

**Почему Kilo Code:**
- **TypeScript**: наш стек, можем эффективно развивать.
- **MIT-лицензия**: полная свобода действий.
- **Готовая экосистема**: VS Code, JetBrains, CLI, Cloud — сразу из коробки.
- **26 000+ звёзд**: активное сообщество.
- **500+ моделей**: не нужно интегрировать провайдеров по одному.
- **Современная архитектура**: SolidJS + OpenTUI, tree-sitter, и т.д.

Kilo Code дал нам готовую платформу с IDE-расширениями, CLI, роутингом моделей
и TUI — мы начали не с нуля, а с топового open-source продукта.

**MiMo-Code** (`github.com/XiaomiMiMo/MiMo-Code`) — ещё один форк OpenCode,

## 5. Что такое Harness

**Harness** (англ. «упряжь», «обвязка») — в терминах NoCowboy это **экосистема
MCP-серверов**, которые образуют инфраструктуру для AI-агента.

Термин заимствован из тестирования (test harness — тестовая обвязка). В нашем
случае это «агентская обвязка» — набор инструментов, подключённых к AI-агенту
через Model Context Protocol (MCP).

Состав Harness NoCowboy (все работают как локальные серверы на портах 9200-9219):

| Сервер | Что делает | Порт |
|--------|-----------|------|
| **Tausik** (NUTAUSIK) | Управление проектом: задачи, память, решения, QA | 9204 |
| **Constitution** | AST-базированные правила качества кода | 9216 |
| **Score Engine** | Оценка качества NoCowboy | 9219 |
| **Contract Guard** | Проверка совместимости API-контрактов | 9218 |
| **NCP Validator** | Валидация спецификаций NCP | 9217 |
| **Ralph** | PRD-машина состояний: загрузка → выполнение → верификация | 9210 |
| **PuppetMaster** | Жизненный цикл PM-фреймворка | 9203 |
| **Context7** | Документация по 20 000+ библиотек | 9200 |
| **SQLite** | Прямой доступ к базам данных | 9201 |
| **Puppeteer** | Браузерная автоматизация | 9202 |
| **Git** | Структурированные git-операции | 9205 |

Итого **11 MCP-серверов**, которые и составляют «упряжь» — полную экосистему
для AI-агента, работающую локально, без облачных зависимостей.

**Философия Harness:** AI-агент — не просто чат-болванка, а центр экосистемы
инструментов. Каждый MCP-сервер добавляет агенту новое «чувство»:
- Tausik — чувство проекта (что сделано, что делается)
- Constitution — чувство качества (правильно ли написан код)
- Ralph — чувство процесса (на каком этапе выполнение)
- Score Engine — чувство зрелости

## 6. NoCowboy — что мы сделали с форком

**NoCowboy** — это форк Kilo Code, адаптированный для **1,7 миллиона
русских разработчиков**.

### Что мы изменили:

**1. Никакой зависимости от западных сервисов**
- Kilo.ai gateway (500+ моделей) — удалён. Свои провайдеры.
- Kilo Cloud — удалён. Всё локально.
- Удалены: share-функции, cloud agent, kilo-proxy

**2. Инфраструктура MCP-серверов**
- 11 собственных MCP-серверов вместо экосистемы Kilo
- Все серверы — локальные, не требуют интернета
- Управляются через `nocowboy mcp start/stop/status`

**3. Русские провайдеры LLM**
- YandexGPT (Yandex Cloud)
- GigaChat (Sber)
- Saiga (открытая русская модель)
- Ollama + llama.cpp для полного оффлайна

**4. NoCowboy Score** — собственная система оценки качества

**5. Русскоязычные промпты** — все агенты работают по-русски

**6. 152-ФЗ комплаенс** — локализация данных, согласия, право на удаление

**7. Сжатый бинарник** — 57.7 MB, `nocowboy` одной командой

**8. NPM-публикация** — `npm install -g @nocowboy/cli` или просто `nocowboy`

### Что мы НЕ тронули (оставили от Kilo):
- SolidJS + OpenTUI — лучшая TUI-платформа
- VS Code Extension — ключевой интерфейс
- JetBrains Plugin — для русских разработчиков, многие используют IntelliJ
- Tree-sitter — AST-понимание кода
- Агентов (Code, Plan, Ask, Debug, Review)
- Инструменты: glob, grep, view, write, edit, bash

## 7. Зачем вообще надо было форкать

### Контр-аргумент: «почему не просто плагин к существующему инструменту?»

**Краткий ответ:** Чтобы иметь полный контроль над стеком, не зависеть от
решений западной компании и интегрировать то, что никогда не появится
в западных инструментах.

**Развёрнутый ответ:**

1. **Санкции и блокировки** — западные API отключают русских пользователей.
   Мы не контролируем kilo.ai, openai.com, anthropic.com. Контролируем только
   свой форк.

2. **Провайдеры** — Kilo Code никогда не добавит YandexGPT и GigaChat.
   Это незаметно для западного рынка. Для русского — critical.

3. **Регуляторика** — 152-ФЗ невыполним для западного инструмента, который
   шлёт данные в США. Мы храним всё локально.

4. **Оффлайн** — когда РКН блокирует очередной CDN, Claude Code умирает.
   NoCowboy работает: локальная модель + локальные MCP-серверы.

5. **Экосистема** — 11 MCP-серверов (Tausik, Constitution, Score Engine и т.д.)
   — это инфраструктура, которую никакой западный инструмент не будет
   разрабатывать для русского рынка.

6. **Язык** — полная русская локализация: промпты агентов, интерфейс,
   документация. Западные инструменты делают UI на 50 языках, но их агенты
   мыслят по-английски.

### Контр-аргумент: «зачем Kilo, а не OpenCode напрямую?»

OpenCode мёртв (архивирован). Kilo — живой, активно развивающийся проект
с 26 000+ звёзд. Форк OpenCode на Go потребовал бы переписывания на
TypeScript (наш стек) и создания экосистемы с нуля.

Форк Kilo Code дал нам готовую платформу. Мы сосредоточились на адаптации
для русского рынка, а не на изобретении колеса.

### Контр-аргумент: «зачем не взять Crush (Charm) вместо всего?»

Crush — отличный продукт (26 600+ звёзд), но:
- Лицензия **FSL-1.1-MIT**, не pure MIT
- Нет IDE-расширений (только CLI)
- Нет JetBrains-плагина
- Ориентирован на Hyper-экосистему Charm
