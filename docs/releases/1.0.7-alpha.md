# NoCowboy 1.0.7-alpha — release notes

Живой индикатор roadmap-прогона. Бейдж в промпт-баре стал коротким тумблером
режима, а в сайдбаре появилась секция **Roadmap** с прогрессом, текущим пунктом
и списком оставшихся шагов. Плюс два фикса mcp-цикла (`mcp start`/`mcp status`)
и харнес-гейт, который держит сгенерированные доки в синхроне. Для внутреннего
использования (npm-публикация не выполнялась).

- **Версия:** `1.0.7-alpha`
- **Бинарник:** `packages/opencode/dist/nocowboy-linux-x64.tar.gz` (+ платформенные пакеты)
- **Установка:** `bun run release` → обновляет `~/.nocowboy/bin/nocowboy`
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.0.7-alpha`

## Что изменилось

### Проблема

После v1.0.6 бейдж показывал `[AUTOPILOT]` / `[AUTOPILOT ON]` — только что режим
включён. Нельзя было понять, идёт ли roadmap-прогон или своя цель, и на каком
пункте. Живой roadmap-прогон, который ход за ходом инжектил продолжения, выглядел
как обычный режим.

### Две поверхности, один источник данных

| Поверхность | Что показывает |
|---|---|
| Бейдж в промпт-баре | режим + состояние: `[AUTOPILOT]` / `[AUTOPILOT ▶/⏸]` / `[ROADMAP ▶/⏸]` |
| Секция «Roadmap» в сайдбаре | `done/total`, текущий пункт (`▶`) и оставшиеся actionable-пункты чек-листом |

Длинная строка в бейдже (`[ROADMAP ▶ r16 · 13 · 84/146]`) — плохой DX: она
распирает промпт-бар и дублирует то, что должно жить списком. Поэтому детали
уехали в сайдбар.

Секция «Roadmap» **переиспользует** нативный механизм Todo-сайдбара — слот
`sidebar_content` и компонент `TodoItem` (галочки/`•`/сворачивание `+N more`) — но
данные берёт из события `session.goal`, а **не** из таблицы `todo`. Причина
семантическая: нативный `Todo` — рабочий список агента (per-session, пишется
`todowrite`), roadmap — план проекта. Их смешение дало бы двум писателям конфликт
за один список.

### Поток данных

- `Autopilot.RoadmapSummary` несёт `done`/`total`; новые `currentStage`,
  `actionItems`, `goalStage` считают текущий пункт и чек-лист.
- `Event.Goal` расширен опциональными `stage`/`done`/`total`/`items` (старые
  клиенты декодируют без изменений).
- Публикуется на каждом **bump** прогона, в командах `/goal`/`/autopilot`/
  `/roadmap` и в **seed при подключении клиента** (directory сессии из
  `SessionTable`) — секция заполнена сразу и переживает перезапуск.

### Фикс регрессии из кросс-модельного ревью

Bump-публикация цели использовала `GoalService.get(sessionID) ?? goal` — при
конкурентном `/goal clear` (команда идёт отдельным fiber'ом) bump публиковал
**воскресшую** цель с roadmap-полями после уже ушедшего `null`, и бейдж/секция
оставались включёнными до следующего события. Убран fallback: bump публикует
`null`, когда цель очищена.

### Фикс `mcp start <name>` — порт сервера, а не индекс запуска

`McpStartCommand` вычислял `port = 9200 + results.length`, поэтому запуск
**одного** сервера по имени поднимал его на 9200 независимо от имени (nutausik
садился на порт plugin-registry), тогда как клиент стучится на настроенный
`url` (9210). Порт берётся из `url` сервера в конфиге (авторитетный источник), а
для `local`-серверов без `url` — из его позиции в конфиге (`9200 + i`, как в
`init`). Вынесено в чистую `mcpServerPort` (`nocowboy/mcp/ports.ts`) с
юнит-тестом.

Рядом: `mcp status` показывал `remote`-сервера (localhost-прокси вроде nutausik)
как вечно «stopped», потому что определял состояние по `type` из конфига. Теперь
состояние всегда читается из pid-файла, а настроенный `url` — лишь запасной
заголовок. Проверено на бинаре: `mcp status nutausik` → `running (pid …) — 9210`.

### Харнес: сгенерированные доки не рассинхронизируются

`ROADMAP.md`/`CHANGELOG.md`/`BACKLOG.md` генерируются из `docs/roadmap.json`, но
синхронность ничем не гарантировалась: pre-commit перегенерировал их **после**
`git add` и не делал повторный `git add`, поэтому в коммит уходил устаревший
снапшот; ошибки генератора глотались (`2>/dev/null || true`); режима проверки не
было. Добавлено: `generate-docs.ts --check` (сравнение с диском, `exit 1` при
рассинхроне), pre-commit генерирует (fail loudly) и `git add`'ит доки, pre-push
гейтит `--check` (ловит коммиты с `--no-verify`), скрипты `docs:gen`/`docs:check`.
Фича-документ: [docs/features/docs-sync-guard.md](../features/docs-sync-guard.md).

## Известные ограничения

- npm-публикация не выполнялась (нужен `npm login`); команда:
  `npm publish --access public --tag alpha`.
- Пуш и тег — за владельцем.
- Секция «Roadmap» по умолчанию развёрнута (как нативный Todo) и при ~27
  actionable-пунктах показывает длинный список до клика по заголовку; текущий
  пункт продублирован строкой `▶` и первой строкой чек-листа — осознанная
  косметика, позиция пункта в списке читается лучше.
- Цель, установленная через goal-инструмент (не слэш-команду), публикует
  `session.goal` только на следующем bump/команде/seed — pre-existing, вне
  скоупа этой фичи.
