# NoCowboy 1.3.1 — release notes

Патч-релиз: сборка больше не может быть помечена чужой версией.

- **Версия:** `1.3.1`
- **Тег:** `v1.3.1` (`packages/opencode/package.json` → `1.3.1`)
- **Бинарник:** `bun run release` → `packages/opencode/dist/` (+ обновление `~/.nocowboy/bin/nocowboy`)
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.3.1`
- **Канал:** релиз для внутреннего использования. npm-публикация **не выполнялась**
  (нужен `npm login`); RC-цепочка (пользовательское тестирование) ещё не пройдена.

## Что исправлено

### Билд всегда штампует настоящую версию пакета

`script/build.ts` брал версию как `process.env.NOCOWBOY_VERSION ?? pkg.version`.
Запущенный TUI инжектит `NOCOWBOY_VERSION` в порождаемые shell'ы, поэтому сборка
внутри такого shell'а штамповала версию **родительского** бинарника: дерево
`1.3.0` собиралось в бинарник, сообщающий `1.0.9-alpha`, и футер UI показывал
устаревшее число.

Теперь версия берётся исключительно из `packages/opencode/package.json` через
чистый хелпер `script/nocowboy/build-version.ts` (`resolveBuildVersion`).
Окружение не читается вовсе; отсутствие версии останавливает сборку с ошибкой,
а не подставляет `0.0.0`.

- Регрессионный тест: `test/nocowboy/build-version.test.ts` (в т.ч. проверяет,
  что `build.ts` не содержит `process.env.NOCOWBOY_VERSION`).
- `packaging/publish.sh` больше не экспортирует `NOCOWBOY_VERSION` — костыль
  удалён, а не надстроен сверху.

### Инструментарий релиза классифицирован в ownership-манифесте

`packaging/**` (npm/AUR/Homebrew/release-тулинг, ru-инструкции) теперь
классифицирован как `owned` — пробел в `ownership-manifest.json`, вскрытый
правкой `packaging/publish.sh`.
