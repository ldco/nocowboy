# NoCowboy 1.4.4 — release notes

Патч-релиз, возвращающий доверие к авто-контексту puppetmaster MCP. Дельта 1.4.4 —
автоматический впрыск больше не содержит кэш правил, который дрейфовал от
`AGENTS.md`; в system prompt остаётся только динамическое состояние проекта.

- **Версия:** `1.4.4`
- **Тег:** `v1.4.4` (`packages/opencode/package.json` → `1.4.4`)
- **Бинарник:** `bun run release` → `packages/opencode/dist/<target>/bin/nocowboy`
  (+ обновление `~/.nocowboy/bin/nocowboy` на Linux)
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.4.4`
- **Канал:** релиз для внутреннего использования. npm-публикация **не выполнялась**
  (нужен `npm login`).
- **Основание:** v1.4.2 включил авто-впрыск `pm_inject_context`, который отдавал
  девять захардкоженных правил вместо `AGENTS.md`. Кэш успел разойтись с проектом:
  указывал `$lib/config/site` вместо `src/project/site-config.ts` и терял все
  allowlist/исключения 284-строчного `AGENTS.md`. Агенты начали «исправлять»
  легитимные исключения и ломать работающий код.

## Что нового в 1.4.4

### Авто-контекст без правил (`puppetmaster-mcp-no-rule-injection`)

`pm_inject_context` теперь возвращает только то, чего нет в статичном `AGENTS.md`:

```
PuppetMaster 4 project detected — AGENTS.md is authoritative for framework rules.
PROJECT: <name> mode=<mode> defaultLocale=<locale>
MODULES: faq=ON, team=OFF
```

`compressedRules` удалён вместе со всеми девятью правилами. Единственный источник
правил — `AGENTS.md` проекта, который NoCowboy загружает сам. Явный запрос
`pm_knowledge topic=rules` по-прежнему отдаёт полный набор — это осознанное
действие агента, а не автоматический впрыск.

### Точный путь конфигурации

`TOPICS.state` и `TOPICS.rules` теперь называют `src/project/site-config.ts` как
место, где определены FEATURES/MODULES; `$lib/config/site` — только re-export.
Раньше кэш отправлял агента править framework-баррель.

### Регрессионный тест

`puppetmaster-mcp.test.ts` проверяет, что авто-впрыск содержит `PROJECT:`/`MODULES:`
и **не содержит** `Self-check`, `canonical ui/`, `NO literal`, `validate:pm4`.
Тест `pm_knowledge topic=rules` оставлен без изменений.

### Проверка счётчика таблиц

План предлагал исправить «39 framework tables» на 38. Сверка с
`PuppetMaster4/src/lib/server/db/schema.ts` показала **39** различных
`sqliteTable`-определений — счётчик уже был верным, менять его не стали.
