# NoCowboy 1.0.3-alpha — release notes

Минорная альфа линейки 1.0: NoCowboy научился проходить **целый roadmap сам**, без
человека, который жмёт «continue». Для внутреннего использования (npm-публикация
не выполнялась).

- **Версия:** `1.0.3-alpha`
- **Бинарник:** `packages/opencode/dist/nocowboy-linux-x64.tar.gz` (+ платформенные пакеты)
- **Установка:** `bun run release` → обновляет `~/.nocowboy/bin/nocowboy`
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.0.3-alpha`

## Что добавлено

### Автопилот — прогон roadmap без человека

Раньше ход сессии завершался, как только модель перестала звать инструменты:
автономии не существовало, кто-то должен был нажать Enter. Теперь есть явный
режим autopilot:

- **Harness auto-continue.** `Goal.auto` персистится вместе с целью; на границе
  хода harness сам вкладывает синтетическое сообщение-продолжение (помечено
  `synthetic`), поэтому прогон идёт дальше без единого человеческого «continue».
  Продолжений не больше бюджета цели; при уже стоящей в очереди команде — пропуск.
- **Conductor `/autopilot [scope]`.** Встроенная команда (агент `auto`) ведёт
  один этап за ход: выбрать пункт roadmap → `task(worker)` реализует → обновить
  `docs/roadmap.json` → **reviewer-гейт** (read-only, другая модель) → done/block.
- **Гейт ревьюера проверяет и код, и roadmap.** Этап не закрыт, пока reviewer не
  подтвердит **оба**: (а) фича соответствует acceptance criteria и доказывающие
  тесты реально зелёные; (б) roadmap актуален — статус пункта соответствует
  реальности, `verify-roadmap` проходит, нет устаревших/ложных `done`. Следующий
  этап не начинается до подтверждения; провал возвращает задачу worker'у.
- **Детерминированный гейт.** Harness на каждом продолжении читает
  `docs/roadmap.json` и вкладывает фазу: «закрой текущий in-progress этап» или
  «бери следующий planned». Это не только текст промпта — рамку задаёт harness.
- **Бюджет — реальный лимит.** `goal.maxTurns` (он же `--max-turns`, по умолчанию
  20) задаёт число продолжений; раньше прогон обрывался на 8 ходах и ждал человека.
- **Stall-guard.** Если in-progress этап не меняется 6 продолжений подряд — в
  продолжение вкладывается требование принять решение (закрыть/блок/`/goal clear`);
  на 12 — harness перестаёт инжектить, чтобы не жечь токены впустую.

### Кнопка запуска в TUI

Автопилот запускается мышью, без знания слэш-команды:

- тумблер **`[AUTOPILOT]` / `[AUTOPILOT ON]`** в нижней панели промпта, рядом с
  `[YOLO]` — отражает **живой** статус прогона текущей сессии: сервер шлёт событие
  `session.goal` при постановке/смене/очистке цели, поэтому бейдж горит `ON`
  ровно пока прогон активен, и гаснет сам, когда цель достигнута или бюджет
  исчерпан. Клик при `OFF` открывает диалог scope и стартует прогон; клик при
  `ON` останавливает его (`/autopilot clear`);
- кнопка **Autopilot** вверху сайдбара сессии — видна во всех вкладках;
- пункт **Autopilot — run the roadmap unattended** в палитре команд (`Ctrl+P`).

Слэш-команда `/autopilot [scope]` тоже работает.

### Headless-режим для CI

- `nocowboy run --autopilot "<scope>" --max-turns N` — прогон без TUI.
- `nocowboy run --agent goal "<scope>"` — алиас.
- `nocowboy run --continue` без сообщения — возобновляет прерванный прогон.
- `/autopilot resume` — то же из TUI, **без сброса** цели и бюджета.

## Что исправлено

### Judge цели не мог признать цель достигнутой

В цикл передавался `Provider.Model` (метаданные) вместо language-модели, поэтому
`generateObject` в оценщике всегда падал и результат глушился — цель не могла стать
`met`. Теперь judge получает `provider.getLanguage(model)`, судит **свежий**
транскрипт (а не снапшот начала хода) и только на границе хода.

### `/goal clear the cache` съедалось как команда

Сабокоманды `/goal` матчились по первому слову, поэтому условие, начинающееся с
`clear`/`cancel`/`stop`, исполнялось как команда и цель не ставилась. Теперь —
точное сравнение по всему аргументу.

## Известные ограничения

- npm-публикация не выполнялась (нужен `npm login`); команда:
  `npm publish --access public --tag alpha`.
- Пуш и тег — за владельцем.
- Один-процессный прогон `bun test` (весь пакет) даёт 4767/73 — это взаимовлияние
  тестов (документировано ещё с v1.0.2): те же файлы по отдельности зелёные.
- TUI возобновляет автопилот по следующему действию (`/autopilot resume` или любое
  сообщение), а не автоматически при запуске приложения: авто-старт на старте
  намеренно не включается, чтобы не тратить токены без наблюдателя. Headless
  `run --continue` закрывает unattended-сценарий.
- Чередование worker↔reviewer задаётся протоколом conductor'а, а не форсируется
  harness'ом.
