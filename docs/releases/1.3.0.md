# NoCowboy 1.3.0 — release notes

Веха-релиз: три запланированных вехи октября собраны в один срез —
**v1.1.0 Engine Isolation & Fork Management**, **v1.2.0 Frontend harness**,
**v1.3.0 Agent identity scoping** — плюс крупная работа по TUI-портам,
графу знаний, ревью-гейтам и контексту.

- **Версия:** `1.3.0`
- **Тег:** `v1.3.0` (`packages/opencode/package.json` → `1.3.0`)
- **Бинарник:** `bun run release` → `packages/opencode/dist/` (+ обновление `~/.nocowboy/bin/nocowboy`)
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.3.0`
- **Канал:** релиз для внутреннего использования. npm-публикация **не выполнялась**
  (нужен `npm login`); RC-цепочка (пользовательское тестирование) ещё не пройдена.
  Команда на будущее: `npm publish --access public` из `packages/opencode`
  (для пре-релиза — `--tag alpha`).

55 коммитов с предыдущего тега `v1.0.9-alpha`.

## v1.1.0 — Engine Isolation & Fork Management

Движок отделён от управляемого ядра так, чтобы его можно было менять, сохраняя
права, сценарии и контракты.

- **Манифест движка** (`engine-manifest.json`, `scripts/engine-manifest.ts`) —
  корневой коммит, provenance (явно `declared`, не verified), версии ключевых
  зависимостей, счётчик backport-ledger, drift-гейт (`--check`).
- **Backport-ledger** (`backport-ledger.json`, `packages/opencode/src/nocowboy/backport/ledger.ts`) —
  13 записей: что взято из upstream, зачем, где адаптация и как проверяется.
- **Ownership-манифест** (`ownership-manifest.json`, `src/nocowboy/ownership/manifest.ts`) —
  классы `owned`/`adapted`/`generated` и гейт, запрещающий смешивать.
- **Порты рантайма** — `@nocowboy/runtime` (`runtime/ports`), `@nocowboy/engine-adapter`
  (связывает порты), `EngineAdapter`; редактор через явный `EditPort`
  (`edit-port-batch-safety`), провайдеры через `ProviderPort`
  (`provider-adapters-port` — TLS/baseURL/proxy на границе, без транспортного
  workaround в домене).
- **Migration contract suite** (`test/nocowboy/contracts/01..08`) — гейт миграции
  движка: worker-child, agent-mutation, cost, i18n, edit-roundtrip, memory,
  compaction-goal, tui-navigation.
- **Merge/backport профиль** — read-only профиль NoCowboy для upstream
  (`script/upstream/*`), без legacy OpenCode→Kilo трансформов.

## v1.2.0 — Frontend harness

- **Svelte 5 Runes conditional directive** (`src/nocowboy/svelte-runes.ts`) —
  директива инжектится в системный промпт **только** для Svelte/SvelteKit
  workspace (по `svelte.config.*` или зависимости `svelte`/`@sveltejs/kit`);
  запрещает legacy Svelte 3/4 (`export let`, `$:`, `<slot>`, `on:click`,
  `createEventDispatcher`). Не-Svelte проекты промпт не раздувают.
- **PMSHOPS архитектурный аудит** — в отдельном репозитории (commit `09d5f04`):
  чистая доменная изоляция, framework-agnostic зависимости, строгие границы
  Drizzle↔zod. См. `docs/features/pmshops-architecture-audit.md`.

## v1.3.0 — Agent identity scoping

Душа принадлежит **только** агенту `nocowboy`.

- **Per-agent rule scoping** — `RulesMigrator.KNOWN_MODES` приведён к реальному
  набору агентов (`worker/nocowboy/reviewer/architect/planner/auto`); правила
  `rules-{agent}/` применяются к одному агенту и больше не попадают в общий
  instruction-список (`Instruction.system(agent)`). Soul-правила,
  `soul-engine` (127.0.0.1:9339) и engine-мандат достаются только `nocowboy`;
  auto/worker/architect/reviewer/planner душу не вызывают.

## Движок агентов, память, планирование

- **AgentCatalog** (`src/nocowboy/agent/catalog.ts`) — единая spawn-политика для
  списка и исполнителя.
- **Read-only как исполняемый инвариант** (`planner-reviewer-readonly-contract`) —
  planner/reviewer действительно read-only.
- **Типизированный Handoff** (`structured-handoff`) — `#route:` оставлен как
  совместимый адаптер.
- **Единый MemoryAdapter** (`memory-adapter-unified`) — транспорт NUTAUSIK в одном
  наблюдаемом месте.
- **Stage-machine** (`1ac02c41c1`) — детерминированные стадии по артефактам, не по
  словам.
- **Stop-hook продолжение хода** (`0052616507`) — реально продолжает ход, с
  потолком 8; **AC-verification hook** снова достижим и блокирует (`cc76ee0e69`).
- **Глубокий контекст** — профиль окна `deep-context-2m` (`context-profile`) и
  выбор файлов по diff (+ граф) для deep context.

## Ревью-гейты и спецификации

- **Reviewer model independence** — независимость модели ревьюера проверяема
  политикой.
- **Commitment-boundary gate** — граница обещаний ревью.
- **`/ponytail-review`** — парсер findings по переинжинирингу.
- **5-частный spec-contract делегации** (`spec/contract.ts`) —
  goal/constraints/acceptance/files-touch/files-not-touch.

## TUI и наблюдаемость

- **Асинхронное чтение git** (`git/git-port.ts`) — верхний бар больше не зовёт
  `execSync` в рендере; `unknown`/`error` больше не выглядят как «чистое дерево».
- **Фасадные view-models** — виджеты не лезут внутрь реализации.
- **Порт нижнего бара** — распространение нажатий и навигация в тестируемом порту.
- **Язык интерфейса** — first-class настройка TUI; ключи панелей NoCowboy
  локализованы, `lang` входит в cache key агента.
- **Balance** — неудачный запрос баланса = `unknown`, а не фальшивый ноль.
- **MCP** — промпты серверов превращаются в команды, понятная ошибка на неизвестный
  промпт; приоритет запуска MCP сделан чистым, детерминированным и логируемым.

## Известные ограничения

- **npm-публикация не выполнялась** — нет `npm login`. Тег и пуш — за владельцем.
- **RC-цепочка не пройдена** — пользовательское тестирование (5+ тестеров) не
  проводилось; это гейт для `v1.0.0-rc`/`v1.0.0`.
- **Окружение тестов:** в `packages/opencode/node_modules/.bin/rg` лежал npm-пакет
  `ripgrep@0.3.1` с повреждённым WASM. Он не импортируется нигде в исходниках, но
  `bun run` добавляет `node_modules/.bin` в `PATH`, поэтому `which("rg")` внутри
  тестов под раннером находил битый шим вместо `/usr/bin/rg` → file-search тесты
  (`file/ripgrep`, `file/index`, `tool/glob`, `tool/grep`, `tool/skill`,
  `server/httpapi-file`) падали с «No files found». Это **не** регрессия релиза
  (зависимость и код не менялись с `v1.0.9-alpha`); лечится чистым `bun install`.
