# NoCowboy 1.4.3 — release notes

Патч-релиз чистки унаследованных PM3-имён. Дельта 1.4.3 — переименование
framework-валидатора и canonical rulebook в PuppetMaster4 на PM4, синхронизация
кэша знаний puppetmaster MCP и регрессионный тест, который ловит возврат PM3-строк.

- **Версия:** `1.4.3`
- **Тег:** `v1.4.3` (`packages/opencode/package.json` → `1.4.3`)
- **Бинарник:** `bun run release` → `packages/opencode/dist/<target>/bin/nocowboy`
  (+ обновление `~/.nocowboy/bin/nocowboy` на Linux)
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.4.3`
- **Канал:** релиз для внутреннего использования. npm-публикация **не выполнялась**
  (нужен `npm login`).
- **Основание:** `pm_knowledge` называл rulebook `pm-v3-style-rules.md` и self-check
  `validate:pm3`, хотя блок уже был «PM4 RULES»; источник истины (PuppetMaster4)
  всё ещё держал PM3-имена.

## Что нового в 1.4.3

### PM4-валидатор вместо PM3 (`purge-pm3-validator-names`)

В PuppetMaster4 `scripts/pm3-validator.mjs` переименован в
`scripts/pm4-validator.mjs`, env-переменная `PM3_DB_PATH` → `PM4_DB_PATH`,
а npm-скрипты — `validate:pm4` / `validate:pm4:strict`. Для безопасного перехода
сохранён deprecated shim `validate:pm3` → `validate:pm4`: старые кэши NoCowboy и
ветки продолжают работать, пока не обновятся.

### Кэш знаний синхронизирован

`packaging/mcp-servers/puppetmaster/src/tools/knowledge.ts` теперь ссылается на
`docs/contributing/pm4-style-rules.md` и `npm run validate:pm4` в обоих наборах
правил (полный `topic=rules` и сжатый `pm_inject_context`). Комментарий в коде
фиксирует связь версий: кэш требует PM4-проект с переименованным валидатором.

### Регрессионный тест

`puppetmaster-mcp.test.ts` теперь проверяет `validate:pm4` и отсутствие
`validate:pm3`/`pm-v3` в обоих путях — старая проверка ловила только строку
`PM v3 RULES` и пропускала имена скриптов.

### Документы

`pm-v3-style-rules.md` → `pm4-style-rules.md`; `v2-v3-token-mapping.md` →
`v2-v4-token-mapping.md` (документ описывает переход v2 → текущую версию).
Активные ссылки в AGENTS.md, README, eslint config, CI workflow и docs обновлены.
Исторические `docs/features`, `docs/design-system/evidence`, `docs/legacy` и планы
намеренно не переписаны.
