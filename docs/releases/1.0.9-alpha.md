# NoCowboy 1.0.9-alpha — release notes

Bugfix-релиз: автономная работа больше не упирается в человека. Для внутреннего
использования (npm-публикация не выполнялась).

- **Версия:** `1.0.9-alpha`
- **Бинарник:** `packages/opencode/dist/nocowboy-linux-x64.tar.gz` (+ платформенные пакеты)
- **Установка:** `bun run release` → обновляет `~/.nocowboy/bin/nocowboy`
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.0.9-alpha`

## Что изменилось

Три дефекта, из-за которых автономный прогон (сабагенты, автопилот, roadmap)
вставал или врал о правах.

### 1. `suggest` и `question` больше не блокируются без человека

**Проблема.** Оба инструмента паркуются на промис, который может разрешить
только человек. В сабагент-сессии (spawn через `task`) или в
автопилот/roadmap-прогоне человека нет — промис не разрешается никогда, и
родитель, ждущий результат `task`, встаёт намертво. Симптомы: вечное
«~ Suggesting next step...» у сабагента; roadmap-сабагент предлагает
«review uncommitted changes» и замораживает весь конвейер до ручного клика.

**Исправление.** Добавлен `NoCowboySession.noHumanReason(id)` — возвращает
причину, когда человек не может ответить: `parents.has(id)` (сабагент) или
`GoalService.get(id)?.auto` (автономный прогон). `suggest`
(`nocowboy/suggestion/tool.ts`) и `question` (`tool/question.ts`) вызывают его
первым делом и мгновенно возвращают инструкцию «не вызывай инструмент и не жди
пользователя, продолжай сам». Обычные пользовательские сессии работают как
раньше.

### 2. YOLO действительно снимает read-only потолки агентов

**Проблема.** `Permission.ask` проверял `veto(hardRuleset)` и
`rule.action === "deny"` **до** гранта YOLO. Для `architect`/`planner`/`reviewer`
`hardPermissions()` возвращает весь ruleset агента, поэтому их `readOnlyBash`
(deny `&&`, `|`, `>`, `git add/commit`, `nocowboy *`) переживал YOLO. В
yolo-режиме read-only агент не мог закоммитить или выполнить
`nocowboy roadmap generate` и останавливался с просьбой к пользователю.

**Исправление.** YOLO читается **до** hard-ruleset veto и deny-проверок и снимает
политику агентов, включая read-only потолки. Абсолютными остаются:

- hard-veto для `external_directory`;
- защита конфигов (`nocowboy.json`, `.nocowboy/`, `AGENTS.md`);
- явные `deny` из верхнеуровневого конфига пользователя.

Без YOLO hard-ceiling по-прежнему сильнее сохранённого «always allow».
Контракт YOLO в README обновлён.

### 3. Встроенный Auto-промпт: работай сам, делегируй только параллелизм

**Проблема.** `auto.txt`/`auto.ru.txt` заявляли «ты НЕ делаешь инженерную работу
сам», что плодило сабагентов на одиночные линейные задачи.

**Исправление.** Промпт переписан: по умолчанию делай работу сам; `task` —
исключение для 2+ реально параллельных потоков или изоляции/другой модели; один
линейный шаг делегировать нельзя. Явный NEVER-список и «сомневаешься — делай
сам».

## Проверки

- `bun run typecheck` — чисто (`tsgo packages/opencode` + `turbo` 9/9 пакетов).
- `bun test test/nocowboy/suggestion/tool.test.ts` — **11 pass**, включая
  «does not block in a subagent session» и «does not block in an autonomous
  (autopilot) session».
- `bun test test/tool/question.test.ts` — «does not block in a subagent
  session».
- `bun test test/nocowboy/server/permission-allow-everything.test.ts` — YOLO
  снимает agent/read-only deny, не снимает config protection и external-directory
  veto.
- `bun test test/nocowboy/permission/` — hard-ceiling без YOLO держится.
- `bun run scripts/verify-roadmap.ts` — все done-features проходят (grep-
  директивы `noHumanReason`, порядок YOLO, правило «работай сам» + фича-документ).
- `bun run docs:check` — сгенерированные доки в синхроне с `roadmap.json`.

## Известные ограничения

- npm-публикация не выполнялась (нужен `npm login`); команда:
  `npm publish --access public --tag alpha`.
- Пуш и тег — за владельцем.
- Полный прогон `test/nocowboy/` на загруженной машине даёт массовые 5-секундные
  таймауты в несвязанных файлах (encoding, external_directory, compaction) —
  набор каждый раз разный, по отдельности всё зелёное. Это перегрузка/шеринг
  состояния тестового окружения, не регрессия.
