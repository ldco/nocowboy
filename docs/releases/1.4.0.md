# NoCowboy 1.4.0 — release notes

Консолидационный релиз: документация приведена к коду. Дельта 1.4.0 — пересборка
`README.md` и починка индекса `docs/`. Ниже — и дельта, и полная инвентаризация
того, что собрано к версии 1.4.0.

- **Версия:** `1.4.0`
- **Тег:** `v1.4.0` (`packages/opencode/package.json` → `1.4.0`)
- **Бинарник:** `bun run release` → `packages/opencode/dist/<target>/bin/nocowboy`
  (+ обновление `~/.nocowboy/bin/nocowboy` на Linux)
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.4.0`
- **Канал:** релиз для внутреннего использования. npm-публикация **не выполнялась**
  (нужен `npm login`); RC-цепочка (пользовательское тестирование) ещё не пройдена.

## Инвентаризация: что собрано к 1.4.0

### Ядро и запуск

- Единый бинарник на Bun (`bun build --compile`), Node.js в рантайме не нужен.
- **Ленивый реестр команд** (`src/cli/registry.ts`): `--version`/`--help`
  отвечают без загрузки telemetry/auth/DB, а любой вызов импортирует ровно один
  модуль команды вместо всего графа (~1400 модулей).
- Провайдер-агностичный runtime: любой OpenAI-совместимый endpoint или локальная
  модель (Ollama).

### Агенты

- Роли: **auto** (диспетчер, по умолчанию), **architect**, **planner**, **worker**,
  **reviewer**, **nocowboy** (собеседник). Переключение — `Tab`/`Shift+Tab`.
- Read-only/ограниченные роли обеспечиваются пермишенами, а не соглашением.
- Subagents, agent-teams, per-agent промпты и модели, per-agent rule-скоупинг.

### TUI

- SolidJS + OpenTUI: реактивный alternate-screen без ручных ANSI-записей.
- Keymap на лидер-клавише (`Ctrl+X`): агенты, модели, темы, сессии, компакция.
- Сайдбар, палитра команд (`Ctrl+P`), диалоги, темы (встроенный набор + nocowboy),
  локализация панели, фоновые процессы, веб-хуки Channels.

### Провайдеры и модели

- Каталог моделей из бандл-снимка `models.dev` (+ live refresh, кэш).
- Стоимость/лимиты/варианты моделей; баланс провайдеров; `small_model`,
  `subagent_model`, per-agent `fallback_model`.

### Контекст, компакция, бюджет

- `compaction.auto`/`prune`/`tail_turns`, `context_profile`
  (`compact`/`standard`/`deep`), `budget` (`max_cost_usd`/`max_tokens`/
  `on_exceed: downgrade|abort`), `tool_output.max_lines`/`max_bytes`.
- Watchdog-и стрима: idle / first-event / subagent-stall — провайдер не вешает ход.

### Инструменты

- Реестр инструментов: `read`, `grep`, `glob`, `edit`, `write`, `apply_patch`,
  `search_replace`, `bash`/shell (tree-sitter-парсинг), `task`, `todowrite`,
  `webfetch`/`websearch`, `lsp`, `skill`, `question`, repo-clone/overview,
  background-jobs, и MCP-инструменты.
- Быстрый выбор edit-инструмента по возможности модели
  (`experimental.tool_capabilities`), а не по имени модели.

### Память (NUTAUSIK)

- NUTAUSIK — глобальный MCP-сервер памяти (порт 9210): задачи, память, решения,
  ADR, handoff. Project-scoped каждый вызов. Auto-wiring: старт сессии →
  авто-создание task, конец сессии → handoff + compact.

### Индексация и граф знаний

- Первоклассная индексация (не плагин), selector эмбеддеров, AST-граф знаний и
  LLM-сводка по нему, repomap.

### MCP

- Единый фреймворк запуска (`resolveCommand`), first-party пакеты
  `@nocowboy/mcp-*`, дефолтные third-party, fault-isolation по клиенту.
- CLI: `mcp add|list|start|stop|status|logs|install|remove|auth|debug|proxy`.

### Расширения (плагины/SDK)

- Публичный контракт кастомных инструментов (`@nocowboy/plugin`: `tool`,
  `tool.schema`, `ToolContext`), lifecycle-хуки, TUI-плагины, авто-дискавери
  из `<config-dir>/plugin(s)/*`.
- Кастомные агенты (`agent/*.md` или config) и команды (`command/*.md`).

### Автопилот и roadmap

- Harness auto-continue (без «продолжай»), `/autopilot` (режим) vs `/roadmap`
  (цель «добить roadmap», детерминированное завершение из `roadmap.json`),
  reviewer-гейт, бюджет ходов, live-индикатор прогона.
- `docs/roadmap.json` — единственный источник правды; `ROADMAP.md`/`CHANGELOG.md`/
  `BACKLOG.md` генерируются; DONE-пункт обязан иметь verify-директивы.

### Управление форком (provenance)

- `engine-manifest.json` (`scripts/engine-manifest.ts`, `--check`) — root commit,
  provenance (`declared`, не verified), версии ключевых зависимостей, ledger-счётчик.
- `backport-ledger.json` — что взято из upstream, зачем, где адаптация и как проверяется.
- `ownership-manifest.json` — классы `owned`/`adapted`/`generated` + pre-commit гейт.

### Качество и гейты

- `.husky/pre-commit`: форсированный `bun turbo typecheck --force`,
  `quality-ratchet` (пустые catch обязаны объясняться), ownership --check-staged,
  generate-docs + `verify-roadmap` (каждый DONE-пункт против кода).
- `docs:check` держит сгенерированные доки в синхроне.

### Локализация

- `lang` (`ru`/`en`): русские системные промпты и UI, поддержка
  YandexGPT/GigaChat-моделей.
