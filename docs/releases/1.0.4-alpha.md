# NoCowboy 1.0.4-alpha — release notes

Автопилот вышел в интерфейс: запуск мышью, живой индикатор статуса, аккуратный
тулбар. Для внутреннего использования (npm-публикация не выполнялась).

- **Версия:** `1.0.4-alpha`
- **Бинарник:** `packages/opencode/dist/nocowboy-linux-x64.tar.gz` (+ платформенные пакеты)
- **Установка:** `bun run release` → обновляет `~/.nocowboy/bin/nocowboy`
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.0.4-alpha`

## Что добавлено

### Запуск автопилота из UI

Раньше автопилот жил только в слэш-команде. Теперь:

- **кнопка Autopilot** вверху сайдбара сессии — видна во всех вкладках;
- пункт **Autopilot — run the roadmap unattended** в палитре команд (`Ctrl+P`);
- **тумблер `[AUTOPILOT]` / `[AUTOPILOT ON]`** в нижней панели промпта, сразу
  после `[YOLO]`.

Клик открывает диалог scope и запускает прогон на текущей сессии (пустой scope =
весь roadmap; можно дописать `--max-turns N`). Слэш-команда `/autopilot [scope]`
тоже работает.

### Живой статус прогона

Тумблер `[AUTOPILOT]` отражает **реальное** состояние цели сессии, а не намерение
клиента:

- сервер шлёт событие `session.goal` при постановке, изменении (счётчик ходов) и
  очистке цели (команды `/goal`, `/autopilot` и цикл сессии в конце хода);
- при подключении клиента сервер сразу отдаёт текущее состояние по каждой
  активной цели — поэтому бейдж корректен **и после рестарта**, а не только после
  следующего изменения;
- бейдж горит `ON`, пока прогон активен, и гаснет сам, когда цель достигнута или
  исчерпан бюджет. Клик при `ON` останавливает прогон (`/autopilot clear`).

### Тулбар промпта

`[Attach]` и `[Paste]` заменены компактными **монохромными** иконками Nerd Font
(paperclip и clipboard); иконки действий (`attach`, `paste`, `⟲`, `▶`) собраны в
один тулбар справа.

Порядок правой панели: `[YOLO] [AUTOPILOT]  attach paste  ⟲  ▶  [🎙 Voice]`.

## Известные ограничения

- npm-публикация не выполнялась (нужен `npm login`); команда:
  `npm publish --access public --tag alpha`.
- Пуш и тег — за владельцем.
- У события `session.goal` пока нет сгенерированного типа в SDK — TUI сужает его
  кастом; полный реген SDK (`packages/sdk/js`) сделал бы его типизированным.
  На поведение не влияет.
- TUI возобновляет автопилот по следующему действию (`/autopilot resume` или
  любое сообщение), а не автоматически при запуске приложения (осознанная
  граница — чтобы не тратить токены без наблюдателя); headless `run --continue`
  закрывает unattended-сценарий.
- Чередование worker↔reviewer задаётся протоколом conductor'а, а не форсируется
  harness'ом.
