# NoCowboy 1.0.2-alpha — release notes

Минорная альфа линейки 1.0: цепочка агентов снова работает, а модель агента можно
назначить там, где работаешь. Для внутреннего использования (npm-публикация не
выполнялась).

- **Версия:** `1.0.2-alpha`
- **Бинарник:** `packages/opencode/dist/nocowboy-linux-x64.tar.gz` (+ платформенные пакеты)
- **Установка:** `bun run release` → обновляет `~/.nocowboy/bin/nocowboy`
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.0.2-alpha`

## Что добавлено

### Ручной маппинг «агент → модель» прямо в TUI

Бэкенд поддерживал `agent.<name>.model` давно, а диалог `DialogAgentModel` был
написан — но не подключён никуда (ни импорта, ни команды, ни привязки) и вызывал
SDK неверно. Теперь его можно открыть двумя путями:

- палитра команд → **Agent models**, слеш `/agent-models`;
- сайдбар сессии → секция **«Модели агентов»**, рядом с Code Indexing и LSP.

Выбор пишется в `~/.config/nocowboy/nocowboy.jsonc` как
`agent.<name>.model = "provider/model"`. Исправлено три дефекта записи: вызов
`sdk.client.config.overlayUpdate` (а не `sdk.client.overlayUpdate`), вложенный
payload (плоские `a.b.c`-ключи не раскрываются) и строка `provider/model` вместо
объекта — `ConfigModelID` это именно строка.

### Смена модели из футера сохраняется

Выбор модели внизу (футер промпта → `DialogModel`) применялся только в текущем
процессе: после перезапуска молча возвращалась модель из конфига (`#9050` —
намеренное правило «конфиг агента побеждает устаревшие локальные выборы»).
Теперь выбор дополнительно пишется в конфиг агента, поэтому нижний селектор и
диалог настроек сходятся к одному источнику — `agent.<name>.model`.

## Что исправлено

### `#route` больше не игнорирует названного агента

Авто-роутер читал директиву `#route: <агент>`, находил агента, проверял
`mode !== "subagent"` — и перезапускал цикл на той же сессии, **не применяя его**.
`runLoop` берёт агента из последнего пользовательского сообщения и модель оттуда же,
поэтому директива исполнялась под прежним агентом. Практическое следствие:
`architect` (у которого нет ни `task`, ни `edit`) не мог передать работу и просил
«снять edit deny / переключить в worker».

- `LoopInput.agentOverride` + учёт его в `runLoop`: агент, модель и variant берутся
  у адресата; system prompt и permissions следуют за `msg.agent` автоматически
  (`processor.ts`, `llm.ts`).
- Промпт `architect` знает путь к исполнителю (`#route: worker <что сделать>`), а
  `planner` получает общий router-промпт — теперь он тоже может передать реализацию.
