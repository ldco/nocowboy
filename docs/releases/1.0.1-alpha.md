# NoCowboy 1.0.1-alpha — release notes

Хотфикс линейки 1.0. Для внутреннего использования (npm-публикация не выполнялась).

- **Версия:** `1.0.1-alpha`
- **Бинарник:** `packages/opencode/dist/nocowboy-linux-x64.tar.gz` (+ платформенные пакеты)
- **Установка:** `bun run release` → обновляет `~/.nocowboy/bin/nocowboy`
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.0.1-alpha`

## Что исправлено

### NUTAUSIK: сессии больше не остаются без MCP

MCP-клиент подключается к `http://127.0.0.1:9210/mcp` на старте инстанса, а прокси
NUTAUSIK поднимался только при создании сессии — в свежем TUI это могло произойти на
минуту позже. Коннект падал один раз, ретрая не было, и сессия оставалась без
инструментов `nutausik_*` с ошибкой «Unable to connect. Is the computer able to access
the url?».

- Прокси стартует из `NocowboyBootstrap.init` до сборки MCP-состояния, ожидание
  готовности ограничено 3с; после неудачного старта ожидание пропускается на 60с,
  чтобы сломанная установка не тормозила каждый инстанс (`f73924cfc6`, `dc125875f1`).
- `hasNutausik()` больше не кэширует отрицательный ответ на 30 секунд (`f73924cfc6`).

### Paste: текст из буфера на Wayland

`Clipboard.read()` использовала `wl-paste` только для картинок, а текст читала через
`clipboardy` → `xsel` (X11-буфер). На Wayland копия из Wayland-приложения для `xsel`
невидима, поэтому чтение возвращало `undefined` и кнопка `[Paste]` ничего не вставляла.

- Текст читается из нативного буфера `wl-paste --no-newline` при `WAYLAND_DISPLAY`,
  с fallback на `clipboardy`; чтение ограничено 2с, чтобы зависший владелец буфера не
  подвешивал команду (`f1dda2730f`, `dc125875f1`).
