# NoCowboy 1.4.2 — release notes

Патч-релиз интеграции с PuppetMaster 4. Дельта 1.4.2 — выравнивание
puppetmaster MCP и детекта PM под актуальный PM4, включение MCP скоупом на
проект и один сквозной тест-набор на конфиг/инъекцию.

- **Версия:** `1.4.2`
- **Тег:** `v1.4.2` (`packages/opencode/package.json` → `1.4.2`)
- **Бинарник:** `bun run release` → `packages/opencode/dist/<target>/bin/nocowboy`
  (+ обновление `~/.nocowboy/bin/nocowboy` на Linux)
- **Проверка:** `~/.nocowboy/bin/nocowboy --version` → `1.4.2`
- **Канал:** релиз для внутреннего использования. npm-публикация **не выполнялась**
  (нужен `npm login`).
- **Основание:** MCP и авто-проводка были захардкожены под удалённый
  `project/puppet-master.config.ts`, из-за чего PM4 не детектировался.

---

## Что нового в 1.4.2

### Детект PM4 в одном месте (`puppetmaster-mcp-pm4-alignment`)

Новый `packages/opencode/src/nocowboy/puppetmaster.ts` определяет PM4 по
`src/project/pm.config.ts`, `src/lib/config/modules.ts` или
`package.json.name === "puppetmaster-4"`. Мёртвый v2/v3-путь намеренно не
принимается. Три прежние точки детекта (`nutausik-client`,
`nutausik-auto-wire`, `session/system`) используют этот модуль.

### PM-контекст через MCP-сервис

В `MCP.Service` добавлен `call(server, tool, args)`. `pm_inject_context`
вызывается у уже подключённого stdio-клиента puppetmaster, а не сырым HTTP к
прокси на `:9201`; инъекция выполняется только при `status === "connected"`.
`fetchPmContext` удалён.

### MCP читает типизированный конфиг PM4

- `pm_config_get` / `pm_inject_context` читают `PM_CONFIG` и
  `MODULE_MANIFEST` (`src/project/pm.config.ts` + `src/lib/config/modules.ts`).
- `pm_config_set` принимает только уникальные scalar-листья внутри блока
  `export const PM_CONFIG`; массивы/объекты отклоняются, `$&`/`$'` пишутся
  литерально, запись валидируется через временный импорт и атомарный
  `rename`. `modules.<id>.enabled` переключает `moduleEnabled` и
  `defaultEnabled` вместе (публичный роут + админка), admin-страницы
  отклоняются.
- `pm_status` / `pm_init` / `pm_dev` переведены на реалии PM4: Vite `5173`,
  SvelteKit-зависимости, `npm run dev` с `predev`.
- `pm_knowledge` переписан: SvelteKit 2 + Svelte 5 runes + Tailwind v4,
  `ui/`-слой, async libSQL (`@libsql/client`, 39 таблиц), ModuleManifest,
  модули `faq/contact/contacts/portfolio/blog` + пять опциональных, без
  page/CMS. Security/compliance сохранены.

### Скоупинг на проект

PM4 `.nocowboy/nocowboy.jsonc` включает `puppetmaster` с
`PM_PROJECT_ROOT` и запуском `bun .../packaging/mcp-servers/puppetmaster/src/index.ts`.
Глобально MCP остаётся выключенным.

### Упаковка

`packaging/mcp-servers/puppetmaster/src/prompts.ts` был неотслеживаемым из-за
blanket-паттерна `mcp-servers` в корневом `.gitignore`; без него чистый клон
не запускал MCP. Файл добавлен в git. Сборка релиза теперь сама штампует
`VERSION` в `install.sh` из `packages/opencode/package.json` — раньше жёсткая
`0.7.3` попадала в архивы 1.4.x.

## Известные ограничения

- MCP загружает TS-конфиги через `bun` (tsconfig-алиасы `$lib`); запуск
  обычным node не сможет импортировать `modules.ts`.
- `pm_config_set` не редактирует массивы/объекты — это ручная правка, потому
  что `pm.config.ts` импортируется `svelte.config.js`.
- В `.nocowboy/nocowboy.jsonc` проекта PM4 хранится абсолютный путь к MCP;
  при переносе чекаута NoCowboy его нужно обновить (как и
  `~/.nocowboy/mcp/launch.json`).
