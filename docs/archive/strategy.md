## 1. PHILOSOPHY AND MISSION

### Context
In 2016, the term **"Cowboy Code"** described chaotic, unsafe development in WordPress. In response, the **No Cowboy** concept was created—a symbol of discipline, code purity, and predictability.

In 2026, the landscape has changed. Chaos no longer comes just from bad programmers, but from **Generative AI** and **excessive complexity**. Code is written quickly, but it is often incomprehensible, fragile, and hard to maintain.

### Mission of No Cowboy
**No Cowboy** is the standard of engineering discipline in the AI era. It is the guarantee that development speed (provided by tools like Puppet Master) is not achieved at the expense of quality, security, and architecture.

### Key Principles
1.  **No Magic:** Every line of code is understandable and justified.
2.  **Contract Before Code:** Interfaces and rules are agreed upon before implementation.
3.  **AI Under Control:** Artificial Intelligence is an executor, not an architect. Architecture is approved by humans through No Cowboy filters.
4.  **Predictability:** The system behaves consistently in dev, stage, and prod environments.

## 3. FUNCTIONALITY OF NO COWBOY CORE

No Cowboy is implemented as a set of tools (CLI + Library + CI Integration) operating on three levels:

### Level 1: No Cowboy Protocol (NCP) — "Before Code"
*Methodology for describing tasks and interfaces.*
*   **Essence:** A unified specification format (based on YAML/JSON Schema) describing business rules, data types, and responsibility boundaries.
*   **Function:** Validation of Task Specification completeness before development begins.
*   **Integration:** Puppet Master reads `.ncp` files and generates typed stubs for frontend (TypeScript) and backend (Pydantic/FastAPI).
*   **Result:** Elimination of discrepancies between the client, analyst, and developer.

### Level 2: AI Governance Layer — "During Code"
*Filter for AI generations and code review.*
*   **Essence:** "Code Constitution"—a set of rules (AST analysis + LLM check) prohibiting anti-patterns.
*   **Rules (Examples):**
    *   Prohibition of `any` in TypeScript.
    *   Prohibition of direct SQL queries in controllers.
    *   Mandatory coverage of critical paths with tests.
    *   Function complexity check (Cyclomatic Complexity < 10).
*   **AI Interaction:** Before commit, code is run through No Cowboy. If AI generates a "hack," the system rejects it and demands refactoring according to the rules.

### Level 3: Live Contract Guard — "After Code"
*Protection against integration breakages.*
*   **Essence:** Dynamic verification of implementation against the declared contract.
*   **Function:** If the backend changes an API response, the frontend build fails with a clear error: *"Breaking Change: Field 'email' is now optional. Fix required by No Cowboy Protocol"*.
*   **Result:** Impossible to silently break integration.

## 4. TECHNICAL IMPLEMENTATION (MVP)

1.  **Core:**
    *   CLI utility in Python/Node.js.
    *   AST (Abstract Syntax Tree) parsers for JS/TS and Python.
    *   Integration with LLM (via Claude/OpenAI API) for semantic code analysis.

2.  **Rule Storage (Constitution):**
    *   Set of configuration files `.nocowboyrc` defining strictness levels for different project types.

3.  **Integration:**
    *   **Pre-commit hook:** Fast style and simple rule checks.
    *   **CI/CD Pipeline:** Deep analysis, contract checks, report generation.
    *   **IDE Plugin (Future):** Real-time highlighting of "cowboy code."

4.  **Visualization:**
    *   Dashboard (Nuxt-based) showing the project's **No Cowboy Score** (0-100%).
    *   Green badge **"No Cowboy Approved"** for audited modules.
